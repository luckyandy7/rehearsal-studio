# Framer 레퍼런스 기반 전체 UI 개편 계획

작성: 2026-10-23 · 상태: 데스크톱 베타 구현

## 베타 적용

사용자 요청에 따라 기존 화면과 분리한 5151 포트 베타를 추가했다. REHEARSAL_BETA 환경 변수로 테마를 선택하고 .next-beta 빌드 디렉터리를 사용한다. 원본 스타일의 공통 토큰, 상단 내비게이션, 큰 Manrope 워드마크, 설정·세션·리포트·기록·모달 스타일을 적용했다. 모바일 구현은 이번 범위에서 제외한다.

타입 검사 및 베타 프로덕션 빌드 통과. 프로덕션 5151에서 studio-browser와 learning-browser 시나리오를 1280/1440px로 실행해 통과했다. 테스트 출력의 “4 widths”는 기존 고정 문구이며 이번 실행은 두 데스크톱 너비다. 개발 서버의 마이크 종료 버튼 타임아웃은 프로덕션 재실행에서 재현되지 않았다. 실제 OpenAI 호출은 이번 검증에 포함하지 않았다.

## 목표와 근거

로컬 export `framer-contextual-badger-802775-fresh-mirror-uzdh/`의 Asher Vale 디자인을 리허설 전체 화면의 기준으로 삼는다. 홈을 로컬 브라우저에서 확인했으며, 하위 페이지 7개는 구현 착수 시 데스크톱·모바일로 추가 조사한다.

확인한 특징은 #f5f5f5 바탕, #050505 텍스트, Manrope, 큰 워드마크, 넓은 여백, 간결한 상단 내비게이션, 검정 CTA, 작품 중심 구성이다. 원본 배경 질감과 메뉴·스크롤 효과의 정확한 수치는 추가 추출한다.

목표는 이 시각 언어로 홈·설정·면접·발표·리포트·기록·모달을 일관되게 재구성하는 것이다. 실제 AI/데모 구분, 질문 출처, 데이터 처리 동의, 키보드 접근성을 포함한 기존 기능은 완료 기준으로 검증한다.

## 1. 레퍼런스와 토큰 확정

- 홈·about·projects·상세·contact를 390/768/1440px에서 캡처한다. 메뉴 열린 상태와 스크롤 중간도 확인한다.
- 배경, 글자, 선, 버튼, 여백, 폭, 타이포, 모션을 computed style과 화면으로 함께 기록한다.
- DESIGN.md를 새 방향으로 재정리한다. 기존 누적 CSS 위에 덮어쓰는 방식 대신 토큰과 컴포넌트별 규칙을 정리한다.
- 기본 제안: canvas #f5f5f5, ink #050505, surface #ffffff, muted #5c5c5c, line #d9d9d9. 실제 대비 검사 후 확정한다.
- 영문은 Manrope, 한국어는 기존 한국어 폰트 자산을 점검해 대응한다. 원본 영문 자간을 한국어에 그대로 적용하지 않는다.
- 홈 제목 64–112px, 작업 화면 제목 28–40px, 본문 16px을 시작점으로 화면 검증한다. 모바일 제목은 36–52px 범위로 조정한다.
- 면접 파랑·발표 초록은 모드 라벨과 진입 영역의 절제된 강조로 유지한다. 녹음 빨강, 힌트 초록, 경고·오류 의미색을 분리한다.
- export의 사진·폰트·템플릿 이용 조건을 확인하고 재사용 자산과 출처를 THIRD-PARTY.md에 기록한다. 작품 사진과 포트폴리오 카피는 리허설 내용으로 대체한다.

## 2. 공통 UI와 내비게이션

주요 파일: src/components/ui.tsx, studio-app.tsx, screens.css, src/app의 전역 스타일.

- 큰 브랜드 타이포와 얇은 선을 사용한 공통 헤더를 만든다.
- 홈·설정·기록에서는 상단 내비게이션으로 주요 화면을 드러낸다. 모바일은 현재 위치가 보이는 메뉴로 접는다.
- 연습 중에는 종료·리포트 생성과 연결 상태가 보이는 전용 헤더를 사용한다. 다른 화면 이동 시 기존 확인 흐름을 연결한다.
- 버튼, 입력, 선택 카드, 상태 라벨, 탭, 빈 화면, 알림, Dialog를 먼저 만든 뒤 화면에 적용한다.
- 버튼은 검정 채움/선/텍스트 위계를 명확히 하고 hover·focus·disabled·loading을 모두 정의한다.
- 표면마다 박스를 씌우기보다 여백·정렬·구분선으로 그룹을 만든다. 입력 영역과 클릭 가능한 요소는 별도 경계와 상태로 구분한다.

## 3. 화면별 적용

| 홈 | 큰 리허설 워드마크, 짧은 소개, 면접·발표 두 진입 영역, 실제 최근 기록. 첫 화면 안에서 시작 버튼 접근 가능 | home.tsx |

홈의 대형 타이포를 실시간 작업 화면에 그대로 반복하지 않는다. 연습방은 텍스트 가독성과 조작 밀도를 우선해 같은 디자인 언어의 작업용 변형으로 만든다.

## 4. 모션

- 기존 Motion과 레이아웃 모션을 사용한다. Framer export 런타임을 앱에 통째로 추가하지 않는다.
- 홈 최초 진입은 타이포와 모드 진입 영역이 함께 나타나는 짧은 시퀀스로 구성한다.
- 화면 전환, 메뉴, 모달, 펼침, 알림 퇴장·아래 요소 이동을 공통 타이밍으로 정리한다.
- 상태 변화마다 높이가 출렁이지 않도록 자막·장치 상태 공간을 확보한다.
- reduced-motion에서는 즉시 전환 또는 짧은 opacity로 대체한다. 마이크·카메라 정리는 애니메이션 완료를 기다리지 않는다.

## 5. 구현 순서와 중간 완료 조건

1. 원본 전체 조사·화면 매핑·토큰 확정 → DESIGN.md에 근거와 적용 규칙 기록.
2. 공통 UI·홈·내비게이션 → 실제 한국어 내용으로 데스크톱/모바일 방향 확인.
3. 면접·발표 설정·입장 모달 → 자료 입력부터 입장까지 막힘 없이 진행.
4. 면접방·발표방·코칭 도구 → 실제 상태별 화면과 장치 수명 확인.
5. 리포트·복습·재도전·기록 → 저장한 기존 기록도 정상 열기.
6. 전체 회귀·스크린샷·README/QA 최신화 → GitHub 반영.

기능 로직과 시각 변경을 구분해 검토한다. 훅·API·저장 스키마는 화면 변경에 필요한 연결 지점을 제외하고 기존 계약을 사용한다. CSS 교체 후 불필요해진 이전 규칙과 중복 모션을 정리한다.

## 6. 완료 검증

- 320/390/768/1440px에서 홈·설정·입장·세션·리포트·기록과 모바일 메뉴 확인. 가로 넘침과 CTA 가림 없음.
